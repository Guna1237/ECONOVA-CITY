## Proposed copy

| Current | Proposed |
|---|---|
| The city refused that | Action not completed. Follow with the safe, specific reason and next step. |
| The city is resolving | Waiting for the next turn, or the actual pending phase. Do not guess the phase. |
| The last action has no confirmed receipt | We could not confirm your last action. Check the updated board and your resources before continuing. Your action was not sent again. |
| Holdings | My properties |
| Goal | Secret objective |
| Commit influence | Submit votes, with the exact amount spent shown beside it |
| Yours alone: no one else can see this | Other players cannot see your objective. |
| Worth 200 at scoring | Earn 200 points if you meet this condition at game end. |
| View the demonstration board | Preview the board |

Use Credits, Influence, Actions, property, and round consistently. Avoid invented city metaphors in errors. Sentence case, short sentences, no em dashes in new player copy. Error text must never expose stack traces, secrets, or private state.

## Phase 1: fix play and comprehension

1. Correct Council allocation, abstaining, and privacy wording.
2. Repair Develop selection and expose the existing Influence action. Confirm all target-specific validation remains authoritative.
3. Agree the smallest server quote/eligibility extension needed for accurate displayed costs. Cover stale state and modified costs before wiring controls.
4. Fix shared dialog semantics and keyboard lifecycle before using it for help.
5. Add a visible **How to play** button on Join, lobby, and the player rail. Provide a short first-read guide plus expandable On your turn, Auctions, Council, Scoring, and Connection help. Use the companion player handout as editorial source, not copied engine calculations.
6. Help must work before joining and while offline. It must not pause timers, clear drafts, send commands, or obscure an urgent pending decision without a visible way back. Prefer inline contextual help within mandatory decisions rather than stacked competing modal focus traps.
7. Replace unclear status/error copy and add Return to join in the demo without signing out live players.

Completion: tests demonstrate every existing legal action is reachable, invalid actions remain rejected, allocations can preserve Influence, modified prices are accurate, dialog focus is contained/restored, and help is reachable without changing game state.

## Phase 2: refine hierarchy and readability

Recommended layout: retain the board and desktop side panel. On phones, prioritize whose turn, time, required decision, and action controls; keep board inspection available. Preserve district colors and current typefaces. Use existing tokens with clearer body/caption hierarchy, contrast-tested instructions, visible focus, and generous touch targets.

Alternative: keep all placement unchanged and add help/copy fixes only. This has lower visual regression risk but does not solve action discoverability as well. Recommendation: adopt the action-first refinement after Phase 1, with before/after mobile browser review.

Admin: use human phase labels and clear pending/complete/error feedback; keep IDs and versions available in diagnostics. Do not change reauthentication, audit-before-response, private payload lifetime, or room binding. Projector: retain public-only state and distance-readable turn/event information. Do not show private balances/cards to make it feel busier.

Completion: inspect narrow and short phones, desktop and projector resolution, long names, empty holdings, full hands, all mandatory decisions, offline/paused/reconnect states, keyboard navigation, and zoom. No color/font changes beyond the approved refinement without explicit agreement.
